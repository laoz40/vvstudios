# Admin sessions inbox and archive

Replace the **Show due** / **Show archived** checkbox model with two tabs: **Inbox** (unarchived admin pile) and **All sessions** (every booking, archived or not). Server-side lists per tab. `hiddenAt` stays the archive flag. Editors stop treating archive as “gone.” Auto-archive when a session is fully done, or when `status` becomes a dead checkout/lifecycle value (`cancelled`, `abandoned`, `expired`). Keep actionable failures in inbox (`failed`, `email_failed`).

- **Inbox** = bookings where \`hiddenAt\` is unset (server query only). Includes actionable problems: \`failed\` (paid but confirmation broke: slot conflict, calendar create, invalid input) and \`email_failed\` (confirmed, receipt email failed).

- **Auto-unarchive** when a new unpaid invoice is attached to an archived booking, only if \`status\` is \`confirmed\` or \`email_failed\` (never for \`cancelled\` / \`expired\` / \`abandoned\` / \`failed\`).
- **Editors**: \`hiddenAt\` does not hide sessions or block deliverables. \`cancelled\` and non-confirmed statuses still block editors as today.`}

## Stage 3 — Auto-archive and auto-unarchive

**Goal:** Inbox shrinks when work finishes or a booking dies, without a cron. One module owns the rules.

Add `convex/lib/sessionArchive.ts` (names TBD) with:

- `adminArchivePatch(now?)` → `{ hiddenAt: now ?? Date.now() }` (idempotent if already set)
- `patchBookingWithAdminArchive(ctx, bookingId, patch)` → merges lifecycle patch + `hiddenAt` when needed
- `isSessionEligibleForAutoArchive(session, stripeSummary)` — “fully done” check below
- `maybeAutoArchiveAfterWorkComplete(...)` — called from deliverables + invoice.paid paths
- `maybeUnarchiveForNewWork(...)` — clear `hiddenAt` when new unpaid invoice on active booking

### “Fully done” (server)

Mirror today’s inverted **Show due** check:

- `status` is `confirmed` or `email_failed`
- `sessionStartAt` in the past
- no unpaid Stripe invoices for booking
- `editStatus === "completed"` (**Sent**)

### Dead status (auto-archive on patch)

Whenever a mutation sets booking `status` to one of these, set `hiddenAt` in the **same** `db.patch`:

| Status      | Known write paths (audit in PR)                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------- |
| `cancelled` | `markSessionCalendarEventDeletedService` (admin delete event); `packageScheduling` session cancel |
| `expired`   | `sessionCheckout` checkout expiry                                                                 |
| `abandoned` | `sessionCheckout` abandoned checkout cleanup                                                      |

**Stay in inbox (no auto-archive on status alone):**

| Status            | Why                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `failed`          | Paid or claimed checkout; confirmation failed (`BOOKING_TIME_UNAVAILABLE`, `GOOGLE_CALENDAR_CREATE_FAILED`, `BOOKING_INVALID_INPUT`). Admin fix + `confirmBooking`. |
| `email_failed`    | Confirmed session; invoice/receipt email failed. Retry/resend flows.                                                                                                |
| `confirmed`       | Normal work until “fully done” auto-archive or manual archive.                                                                                                      |
| `pending_payment` | Live checkout until `expired` / `abandoned` or cancel.                                                                                                              |

## Cancel vs archive (reference)

| Action              | Menu label            | Calendar  | `status`                | `hiddenAt`                    | Editors                   |
| ------------------- | --------------------- | --------- | ----------------------- | ----------------------------- | ------------------------- |
| Delete event        | **Delete event**      | Removed   | `cancelled`             | set (stage 3)                 | No access                 |
| Checkout dies       | (automatic)           | —         | `expired` / `abandoned` | set (stage 3)                 | No access                 |
| Confirmation failed | (automatic)           | —         | `failed`                | unset (stays in inbox)        | No access until confirmed |
| Email failed        | (automatic)           | —         | `email_failed`          | unset until done auto-archive | Access like confirmed     |
| Archive             | **Archive session**   | Unchanged | Unchanged               | set                           | Still access (stage 1)    |
| Unarchive           | **Unarchive session** | Unchanged | Unchanged               | cleared                       | Unchanged                 |
