# Admin sessions inbox and archive

Replace the **Show due** / **Show archived** checkbox model with two tabs: **Inbox** (unarchived admin pile) and **All sessions** (every booking, archived or not). Server-side lists per tab. `hiddenAt` stays the archive flag. Editors stop treating archive as “gone.” Auto-archive when a session is fully done, or when `status` becomes a dead checkout/lifecycle value (`cancelled`, `abandoned`, `expired`). Keep actionable failures in inbox (`failed`, `email_failed`).

- **Inbox** = bookings where \`hiddenAt\` is unset (server query only). Includes actionable problems: \`failed\` (paid but confirmation broke: slot conflict, calendar create, invalid input) and \`email_failed\` (confirmed, receipt email failed).
- **All sessions** = every booking, archived and unarchived. Archive is filing state (`hiddenAt`), not a separate booking status. Stage 2 does not add an archived badge; use **All sessions** tab or manual archive actions to see filed rows.
- **Archive** = set \`hiddenAt\` (drops off inbox, still visible on **All sessions**). **Unarchive** = clear \`hiddenAt\` (back to inbox). Schema unchanged.
- **Manual archive** stays; rare once auto-archive ships. Confirm if archiving while deliverables are not **Sent** and an editor is assigned.
- **Auto-archive (done)** when \`confirmed\` or \`email_failed\`, past, no unpaid Stripe invoices, deliverables **Sent** (\`editStatus === "completed"\`). Event-driven only; no cron. \`email_failed\` is eligible for this path once work is truly finished (same as confirmed).
- **Auto-archive (dead status)** when \`status\` becomes \`cancelled\`, \`abandoned\`, or \`expired\` — same patch sets \`hiddenAt\` via one helper. Includes admin **Delete event** and checkout cleanup. **Not** \`failed\` or \`email_failed\`.
- **Do not** auto-archive live \`pending_payment\` until \`expired\` / \`abandoned\` (or admin cancels).
- **Auto-unarchive** when a new unpaid invoice is attached to an archived booking, only if \`status\` is \`confirmed\` or \`email_failed\` (never for \`cancelled\` / \`expired\` / \`abandoned\` / \`failed\`).
- **Editors**: \`hiddenAt\` does not hide sessions or block deliverables. \`cancelled\` and non-confirmed statuses still block editors as today.`}

## Stage 2 — Server inbox / all lists + admin UI (shipped)

**Goal:** Inbox vs **All sessions** tabs drive server-side `listSessions`. Remove **Show due** and **Show archived**. Keep **Show unconfirmed** (`includeStale`).

### Schema index (shipped: Option A)

Compound indexes on `bookings`:

- `by_hiddenAt_and_sessionStartAt` — inbox pagination when sorting by session date
- `by_hiddenAt_and_pendingPaymentCreatedAt` — inbox pagination when sorting by createdAt

Inbox queries use `.withIndex(..., (q) => q.eq("hiddenAt", undefined))`. **All sessions** keeps existing `by_sessionStartAt` / `by_pendingPaymentCreatedAt` with no `hiddenAt` filter.

Option B (denormalized `adminInboxVisible`) was not used.

### List API (shipped)

- **`convex/lib/adminSessionList.ts`**: `paginateAdminSessionsBySessionStart`, `paginateAdminSessionsByCreatedAt`, `passesAdminInboxStaleFilter` (stale = expired / abandoned / checkout past 24h; `cancelled` always excluded when `includeStale` is false).
- **`listSessions` args**: `{ paginationOpts, sortBy, sortDirection, view?: "inbox" | "all", includeStale?: boolean }` (defaults: `view: "inbox"`, `includeStale: true`).
- **`includeStale` applies to both views**, not inbox-only.
- Tests: `convex/tests/adminSessionsList.test.ts` (inbox omits archived; all includes archived).

### Admin UI (shipped)

- **`AdminDashboard`**: one `usePaginatedQuery(api.sessions.listSessions, { view, includeStale, sort… })` (not two hook instances; args change when tab or stale toggle changes).
- **`SessionsListViewTabs`**: Inbox / All sessions beside search; input-matched border/background; full-width tab bar on mobile.
- **`SessionsTableFilters`**: **Show unconfirmed** on desktop and in mobile Filters menu for **both** tabs.
- **`filterAdminSessions`**: client search only (`customerFilter` on loaded pages). No server `searchQuery`. Prefetch in `SessionsTable` when search hides all loaded rows.
- **Preferences**: `sessionsView` + `showStaleBookings`; removed `showArchived` and `showUpcomingOnly`.
- **Row UI**: no archived badge; past sessions keep existing muted styling only.

### Not in stage 2

- Auto-archive on deliverables **Sent** (stage 3).
- Dead checkout status `hiddenAt` patches (stage 3).

## Stage 3 — Auto-archive and auto-unarchive

**Goal:** Inbox shrinks when work finishes or a booking dies, without a cron. One module owns the rules.

Add `convex/lib/sessionArchive.ts` (names TBD) with:

- `archiveDeadCheckoutBooking(ctx, bookingId, updates)` → dead checkout field updates plus `hiddenAt`
- `isSessionEligibleForAutoArchive(session, stripeSummary)` — “fully done” check below
- `archiveSessionWhenFullyDone(...)` (or equivalent) — evaluate rules and set `hiddenAt` when eligible
- `unarchiveSessionForNewUnpaidInvoice(...)` — clear `hiddenAt` when a new unpaid booking invoice is recorded

<Callout
	tone="decision"
	body="Stage 2 deliberately did **not** add \`sessionArchive.ts\` or archive-on-sent. Implement all auto-archive behavior in this stage only."
/>

### “Fully done” (server)

Mirror today’s inverted **Show due** check:

- `status` is `confirmed` or `email_failed`
- `sessionStartAt` in the past
- no unpaid Stripe invoices for booking
- `editStatus === "completed"` (**Sent**)

### Dead status (auto-archive on patch)

Whenever a mutation sets booking `status` to one of these, set `hiddenAt` in the **same** `db.patch`:

| Status      | Known write paths (audit in PR)                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------- |
| `cancelled` | `markSessionCalendarEventDeletedService` (admin delete event); `packageScheduling` session cancel |
| `expired`   | `sessionCheckout` checkout expiry                                                                 |
| `abandoned` | `sessionCheckout` abandoned checkout cleanup                                                      |

**Stay in inbox (no auto-archive on status alone):**

| Status            | Why                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `failed`          | Paid or claimed checkout; confirmation failed (`BOOKING_TIME_UNAVAILABLE`, `GOOGLE_CALENDAR_CREATE_FAILED`, `BOOKING_INVALID_INPUT`). Admin fix + `confirmBooking`. |
| `email_failed`    | Confirmed session; invoice/receipt email failed. Retry/resend flows.                                                                                                |
| `confirmed`       | Normal work until “fully done” auto-archive or manual archive.                                                                                                      |
| `pending_payment` | Live checkout until `expired` / `abandoned` or cancel.                                                                                                              |

`pending_payment` stays in inbox until it becomes `expired` / `abandoned` or an admin cancels. **Show unconfirmed** controls visibility of stale unarchived checkout rows on **both** inbox and all lists (same as stage 2).

### Triggers (done path — editStatus **Sent**)

All UI paths that mark deliverables **Sent** call the same mutation: `api.sessions.updateSessionEditStatus` with `editStatus: "completed"`. Stage 3 must run auto-archive from **`updateSessionEditStatusService`** after `saveSessionEditStatus` (one server hook, not separate client-only logic).

| Caller                   | How **Sent** is set                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| Admin deliverables tabs  | `useStatusActions` → `handleUpdateEditStatus("completed")`                                       |
| Admin options menu       | **Set deliverables status to sent** → same hook (`SessionActionsMenu`)                           |
| Admin deliverables email | `useDeliverablesEmailAction` → `updateSessionEditStatus({ editStatus: "completed" })` after send |
| Editor dashboard         | `EditorDeliverableStatusBadge` → `updateSessionEditStatus`                                       |

Manual **Set deliverables status to sent** must auto-archive when the “fully done” rules pass, same as sending the deliverables email or using the **Sent** tab. Do not wire archive only on the email action.

After `invoice.paid`, call the same helper so a session that becomes fully paid + **Sent** archives without a second admin click.
